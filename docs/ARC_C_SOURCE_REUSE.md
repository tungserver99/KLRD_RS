# ARC-Challenge source reuse receipt

`klrd_arc/evaluate.py`, `model.py`, `data.py`, and `artifacts.py` are direct byte copies from the sibling `../KLRD/klrd/` project. `klrd_arc/SOURCE_RECEIPT.json` records their SHA-256 values. `klrd_rs/e3full/arc.py` verifies these bytes before running. The historical `benchmark_saved_run` helper is not used; its original application-only imports remain unchanged in the copied source.

The adapter calls the original `evaluate_utility` with `tasks=['arc_challenge']`. The original driver retains its result serializer, sequential clean/fingerprint pair, batch size 1, context length 4096, zero shots, chat templating, all test examples, 1000 bootstrap iterations, and native HFLM answer-choice likelihood scoring. The comparison uses `acc_norm,none` (length-normalized choice accuracy), not generated answer extraction. The ARC likelihood temperature remains 1; free-generation temperature 0.8 and the 1024-token response cap do not enter ARC scoring.

Both historical manifests (`../KLRD/outputs/klrd/private/manifest.json` and `../KLRD/outputs/klrd_vllm/private/manifest.json`) identify `lm_eval==0.4.13` and `data_seed=20261021`. The separate ARC requirements file must pin that harness. Its official versioned interfaces were inspected as source only: [model cache](https://github.com/EleutherAI/lm-evaluation-harness/blob/v0.4.13/lm_eval/api/model.py), [evaluator](https://github.com/EleutherAI/lm-evaluation-harness/blob/v0.4.13/lm_eval/evaluator.py), [task manager](https://github.com/EleutherAI/lm-evaluation-harness/blob/v0.4.13/lm_eval/tasks/manager.py), and [ARC configuration](https://github.com/EleutherAI/lm-evaluation-harness/blob/v0.4.13/lm_eval/tasks/arc/arc_challenge.yaml).

The original model loader uses BF16. This run deliberately overrides only model construction to use matched FP32 for **all four models**, preserving the frozen teacher's FP32 geometry and native RMSNorm/head. The teacher applies `klrd_rs.math.rotate` with frozen P/Q and angles `strength * (L @ bank[0])` immediately before the final RMSNorm, then uses the native output head. It does not apply a tangent approximation, logits bias, adapter, or likelihood-temperature scaling. Pilot/full students load validated ordinary merged checkpoints without runtime keys or hooks. Hooks and temporary module injections are removed in `finally` blocks. Only one model is resident at a time. Results explicitly state that they are **not numerically equivalent to historical BF16 scores**.

The original driver did not pin an ARC dataset commit. No historical dataset revision is invented. At the first server invocation the adapter freezes the harness source hashes, resolved task configuration, actual test dataset fingerprint/version, ordered test IDs hash, complete ordered document hash, canonical tokenizer vocabulary/template/special-token hashes, and all model/checkpoint identities. Every model and every resume must match them. After native harness request construction it also compares the hash of the exact ordered chat-templated likelihood requests across the four models. The full task config is saved, so the original prompt/choice templates are inspectable without private documents.

The first original evaluator pair produces clean then exact teacher. Later original pilot/full pairs reuse the actual clean result only after its identity, protocol, benchmark/request hashes and committed file hashes agree. No synthetic clean result is created. Per-model `arc_c/{clean,teacher,pilot_student,full_student}/complete.json` records commit checksums as soon as each original result serializer returns; final `arc_c/complete.json` exists only after all four models finish. A completed model result retains the original serializer bytes in `result.json` and records model identity, runtime, evaluated sample count, normalized-correct/total counts, and accuracy in `summary.json`. The normalized-correct count is recovered from the unrounded native accuracy and effective sample count only when the product is integral within a strict tolerance. Partial populations are rejected.

For interrupted jobs, the adapter uses the harness's supported `simple_evaluate(use_cache=...)` path. Its native `CachingLM` installs HFLM partial-response hooks and uses autocommit SQLite. Model/protocol-specific databases live only under `private/arc_c/{model}/`; the cache hook is flushed/closed and detached after evaluation. Successfully cached likelihood requests can be reused on restart; in-flight requests may repeat after preemption. Benchmark scoring, filtering and aggregation remain native. Runtime is elapsed time for the invocation that produces the final result, including cache hits, and excludes earlier interrupted invocations.

Run the explicit `arc-c` phase on the server after full merge, with the pinned base/tokenizer already cached locally. No model downloads occur in the adapter (`local_files_only=True`). Dataset availability follows the original harness loader; prepare/cache it on the server as needed. ARC never chooses or changes a checkpoint. Do not put `private/arc_c` databases or any raw private prompts/responses into review ZIPs. Public artifacts are protocol/config hashes, original aggregate harness outputs, per-model summaries/receipts, and `arc_c/comparison.csv`.

Implementation validation on the local machine was static source inspection and PowerShell SHA-256 comparison only. No Python, tests, mocks, models, numerical checks, API calls, downloads, dependency installations, or PBS submissions were executed.
