# E2 exact vLLM generation implementation plan

User authority: pasted vLLM migration specification, 2026-11-02. It explicitly
overrides all local runtime/test steps in skill templates. DO NOT execute tests,
model loading, benchmarks, installs, dataset reads or experiments locally.

## Design and scope

Target vLLM 0.10.2, V0 engine, FP32/XFormers, TP=PP=1, eager execution. This
version has public lazy ModelRegistry registration and LLM.apply_model. Ordinary
Qwen2 weight names/loaders and attention remain intact. Replace final RMSNorm
with a compatible subclass preserving norm.weight: combine the fused residual,
apply the frozen exact rotation, normalize without a second residual addition.
No logit bias, temperature division, FP64 Linear or HF generation in vLLM.
SamplingParams applies temperature 0.8 once with the existing independent seeds.

The existing HF model is retained ONLY for existing verification and native-token
visited-prefix KL replay, not generation. Preserve its existing numerical policy.
Dedicated spawned vLLM process limits lifecycle interference; reserve 40% of GPU
for vLLM on the existing 40GB A100 with the verifier resident. No precision fallback.
Changing the engine cannot promise cross-engine identical sampled tokens. Keep
all old runs immutable; new run_006 reuses the exact frozen cohort/groups/quality
selection from run_005 if present, with new backend provenance, and no old outputs.
